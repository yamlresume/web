[YAMLResume v0.18](https://github.com/yamlresume/yamlresume/releases/tag/v0.18.0)
正式發布。本次的重頭戲是全新的
[Typst 引擎](/zh-tw/docs/layouts/typst)，讓 YAMLResume 在 LaTeX 之外擁有第二條
PDF 排版路徑。此版本也新增 Italian，將樣例庫從 10 份擴充到 20 份，並改進連結樣式、
PDF 診斷與 AI 提供商預設配置。

## 全新的 Typst 引擎

[Typst](https://typst.app/) 是一套現代化排版系統，提供簡潔且可程式化的語法。
YAMLResume 現在可以將同一份 YAML 內容轉換為 LaTeX 或 Typst 原始碼，並將任一種
原始碼編譯為專業 PDF。

在履歷中加入 Typst 版面配置：

```yml lineNumbers title="resume.yml"
layouts:
  - engine: typst
    template: jake
    typography:
      fontSize: 10pt
      links:
        underline: false
    theme:
      colors:
        accent: burgundy
```

首個 Typst 模板是 [`jake`](/zh-tw/docs/layouts/typst/templates/jake)，移植了簡潔、
ATS 友善的 LaTeX Jake 設計，支援在地化術語、Markdown 摘要、頁面邊距、字型家族、
行距、強調色、章節別名與排序、圖示、URL，以及依語系選擇的 CJK 字型回退。

![Jake Typst 模板](/static/images/docs/layouts/typst/templates/jake-template.webp)

您可以在
[Playground](/zh-tw/playground?sample=software-engineer&locale=en&engine=typst&template=jake)
中查看產生的 Typst 原始碼，或閱讀 [Typst 引擎指南](/zh-tw/docs/layouts/typst)
了解所有選項。

### 安裝與預設版面配置

編譯 PDF 需要 **Typst 0.13.0 或更新版本**。官方 Docker 映像檔已內建 Typst
0.15.1，因此 Docker 使用者無需另外安裝。執行 `yamlresume doctor` 即可檢查本機
環境。

從 v0.18 開始，`yamlresume new` 產生的預設 `layouts` 陣列會包含 Typst 版面配置。
若使用新的預設配置建立履歷，請先安裝 Typst 再建置全部 PDF，或使用官方 Docker
映像檔；若只需要原始檔，可以略過 PDF 編譯：

```console
$ yamlresume build resume.yml --no-pdf
```

現有履歷只要明確配置了 `layouts` 陣列，就會繼續使用原有引擎。當履歷同時啟用
LaTeX 與 Typst 時，兩份 PDF 分別命名為 `resume.tex.pdf` 與 `resume.typ.pdf`，
避免互相覆寫。只啟用一個 PDF 引擎時，仍使用傳統的 `resume.pdf` 檔名。

## 新增 Italian 語系

Italian 以 `it` 加入內建語系，使 YAMLResume 現在支援 **11 種語言、13 個區域
代碼**。它提供在地化的章節標題、教育學位、語言流利度、國家名稱，以及符合義大利語
慣例的小寫月份名稱。

```yml lineNumbers title="resume.it.yml"
locale:
  language: it
```

直接從樣例建立一份義大利語履歷：

```console
$ yamlresume new resume.it.yml --sample software-engineer --language it
```

請參閱 [Italian 語系指南](/zh-tw/docs/locale/italian)，或瀏覽
[義大利語作品集](/zh-tw/gallery/languages/it)。

## 20 份履歷樣例，覆蓋 13 個語系

精選樣例庫已從 10 份翻倍至 **20 份履歷**，涵蓋更廣泛的技術、設計、商業、醫療與
公共服務職位。每份樣例均提供全部 13 個區域代碼的版本，作品集也會為每份在地化履歷
發布 HTML、DOCX、PDF、LaTeX、Typst、Markdown 與預覽圖。

瀏覽[作品集](/zh-tw/gallery)，在終端機列出樣例，或建立一份本機副本：

```console
$ yamlresume samples list
$ yamlresume new resume.yml --sample registered-nurse --language it
```

[Samples 套件文件](/zh-tw/docs/ecosystem/samples)介紹了程式化 API。

## 統一的連結底線控制

`typography.links.underline` 選項現在可一致地套用於 **LaTeX、Typst、HTML 與
DOCX**：

```yml lineNumbers
layouts:
  - engine: typst
    typography:
      links:
        underline: true
```

LaTeX 與 Typst 使用固定基線的底線，LaTeX 也會避開字母下行部分，在不改變文字間距的
情況下保持底線清晰易讀。HTML 與 DOCX 同樣遵循此設定，讓四種視覺化引擎共享統一的
連結樣式約定。

## 更清楚的 PDF 建置診斷

PDF 建置現在會先確認預期檔案存在且非空，再回報成功。LaTeX 與 Typst 編譯器警告也會
直接顯示，不再隱藏在除錯日誌中；Typst 輸出中關於可選 CJK 回退字型的預期警告則會被
過濾。

搭配依引擎區分的 PDF 檔名，這些改進讓多引擎建置更容易理解與排查。

## 更新 AI 提供商預設模型

內建的 AI 產生與翻譯指令現在使用最新的預設模型 ID：

| 提供商   | 環境變數           | 預設模型         |
| -------- | ------------------ | ---------------- |
| DeepSeek | `DEEPSEEK_API_KEY` | `deepseek-flash` |
| Kimi     | `MOONSHOT_API_KEY` | `kimi-k3.1-pro`  |
| OpenAI   | `OPENAI_API_KEY`   | `gpt-5.6-luna`   |
| Ollama   | `OLLAMA_HOST`      | `llama3.2`       |

OpenAI 相容提供商現在統一使用 Chat Completions API。您仍可透過 CLI 選項或環境變數
覆寫模型與基礎 URL；詳情請參閱 [AI 產生指南](/zh-tw/docs/ai/generate)。

## Breaking Change：渲染器類別名稱增加引擎後綴

引入 Typst 後，LaTeX 渲染器類別名稱需要明確區分引擎。如果您直接從
`@yamlresume/core` 匯入渲染器類別，請更新以下名稱：

| v0.17                    | v0.18                         |
| ------------------------ | ----------------------------- |
| `JakeRenderer`           | `JakeLatexRenderer`           |
| `ModerncvBankingRenderer`| `ModerncvBankingLatexRenderer`|
| `ModerncvCasualRenderer` | `ModerncvCasualLatexRenderer` |
| `ModerncvClassicRenderer`| `ModerncvClassicLatexRenderer`|

新的 Typst 實作透過 `JakeTypstRenderer` 提供。YAML 履歷檔案與使用高階渲染 API 的
使用者無需修改配置。
